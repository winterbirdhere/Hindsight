# Rewind performance engine

The independent MIT host in `RewindPerformance` calls official osu! difficulty and performance APIs. It pins `ppy.osu.Game.Rulesets.Osu` to `2026.730.0` and the bundled .NET runtime to `8.0.30`. The old TypeScript PP library is not used for the live counter.

The September 21 audit compared this calculation code with official NuGet `2026.916.0` and release `2026.920.0`. Their material PP change treats a zero legacy score as unavailable (upstream `f599aa874bc09078993bee720422213a8d9f0601`). The host normalizes zero to null to use the same fallback while retaining its .NET 8 runtime. Other inspected difficulty/performance changes were equivalent API cleanups; see `qa/pp-official-audit-20260921` for pinned source hashes, comparisons and independent numerical checks.

Build from the repository root with `npm run performance:build`. A .NET 8 SDK is required to build; users of the packaged application do not need .NET installed. The script runs native reference tests, publishes a Windows x64 helper, preserves dependency licenses/source material, and verifies its JSON protocol before promoting it to `resources/performance-engine`.

The helper accepts one JSON object per stdin line and responds with one JSON object per stdout line. Diagnostic output uses stderr. Electron submits one replay batch and releases the process after receiving its result.

Requests contain `beatmap` text and `calculations`, each with `mode`, native `mods`, and cumulative `states`. See [shared state types](../libs/osu/performance/src/types.ts) and [wire protocol](../libs/osu/performance/src/protocol.ts). Each state must describe a completed contiguous object prefix, contain achieved maximum combo and exact basic/nested judgement counts, and use beatmap timestamps. No future 300s or unfinished slider results should be supplied.

Every prefix uses the official performance calculator, including its effective-miss estimate. Historical maximum combo is supplied, not the current streak. A newly observed slider break does not necessarily produce an immediate large PP loss: the official estimate allows missing slider ends and depends on accumulated score/combo. Rewind does not add a penalty or turn slider breaks into extra misses. Each timeline also carries the official `EffectiveMissCount` of the calculation behind its last point's PP as `effectiveMissCount` (absent when no object was completed); it is read from that calculation, never computed separately, and is not part of `fullDifficulty` or the points.

The counter is PP achieved on the completed contiguous object prefix, not a full-map FC projection. It updates when a prefix resolves and holds between those updates. The final value uses the same reconstructed play and the full-map attributes once the map completes. Calculator endpoint agreement verifies calculation consistency; it does not prove that a replay reconstruction exactly reproduces historical judgements or spinner bonus scores. Missing ScoreV1 data uses the official fallback, including at the endpoint.

Resolved circles publish PP at their actual judgement time, including early hits or misses; SR retains its independent map-time schedule. Earlier unfinished sliders still gate the contiguous prefix. Stable spinner rotation points are reconstructed from retained scored half-turns using Stable's unscaled 100/1100 award rules, so ordinary spinners no longer disable ScoreV1 for the rest of the replay. Missing spinner state and unsupported Spun Out rotation still use the fallback. No saved score or PP is substituted at completion.

Supported configurations include NF, EZ, HD, HR, DT, NC, HT, DC, FL, SO, SD, PF, ScoreV2, DA, and CL at the calculation layer. Replay reconstruction has its own supported-mechanics limits. Native custom rates and DA/CL settings are validated and converted by official APIs. Unknown configurations produce a per-mode error, preserving valid other modes.

`CalculateTimed` runs once per distinct resolved mod configuration. Stable and default Lazer+Classic can share cached difficulty when all resolved mods and settings match; their PP statistics and scoring mechanics remain separate. Every completed-map endpoint is checked against a separate `Calculate` result and performance calculation. Replay PP uses reconstructed statistics and legacy score tables throughout, including the end; saved totals do not overwrite the reconstruction. Unavailable legacy scores use the official combo-based fallback.

Relax follows normal PP in every calculation mode: both performance difficulty attributes and score mods omit RX, preserving all remaining mods and settings, score statistics, and each mode's scoring mechanics. This is an analysis value, not ranked Relax PP, and does not change replay gameplay. Stable also displays normal full-map and progressive SR with RX removed. Native Lazer and Lazer+Classic retain their official Relax SR through a separate cached difficulty configuration. The engine/protocol version invalidates older results.

Run `node tools/performance/verify-pipeline.cjs` for the headless integration check through actual replay reconstruction and Electron's process-worker adapter. Its optional argument is the output JSON report path; use the `REWIND_PERFORMANCE_ENGINE` environment variable to override the default published engine executable. [Verification report](../qa/live-pp-20260904/README.md) documents semantics, sources, tests, and known limits.
